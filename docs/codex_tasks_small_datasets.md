# codex_tasks_small_datasets.md

## Назначение

Этот файл описывает **полный пакет задач** для Codex только по ветке `small-datasets`.

Цель: довести small-datasets код до состояния, в котором он:
- запускается на `mushrooms`, `a9a`, `w8a`;
- корректно учитывает communication budget;
- строит нужные графики;
- не делает лишних вычислений;
- хорошо подходит под запуск на **MacBook Pro M4 Pro**.

---

## 1. Вход

Codex должен использовать как вход:
- исходный код из `bits_complexity_paper-main.zip`;
- `AGENT.md`;
- `docs/article.md`;
- `planned_graphs.md`;
- `docs/planned_graphs_small_datasets.md`.

### Зафиксированные пользовательские ограничения
- обязательные датасеты: `mushrooms`, `a9a`, `w8a`;
- ось `Ox` — это `kbits / n`;
- все кривые внутри одной графической семьи должны заканчиваться одинаково по `Ox`;
- лишние вычисления выполнять нельзя;
- обязательная композиция: `gradient -> DB(4-bit) -> TopK(10%)`;
- в static/dynamic семье нужны `p in {2,4,8}`;
- seed по умолчанию: `42`.

---

## 2. Необходимые действия

### Шаг 1 — переаудировать и стабилизировать код
Нужно:
- проверить текущий рабочий код в `src/bits_complexity` и legacy-расхождения старого архива;
- убрать явно неверные или вводящие в заблуждение места;
- обеспечить воспроизводимость при `seed = 42`;
- сделать минимальную понятную структуру проекта без лишнего рефакторинга.

### Шаг 2 — сделать единую точку входа
Нужен один простой experiment runner, который умеет:
- выбрать датасет;
- выбрать метод;
- выбрать compressor pipeline;
- выбрать static/dynamic режим;
- выбрать bits и `p`;
- выбрать общий `Ox` cutoff;
- сохранить CSV;
- при необходимости построить plot.

### Шаг 3 — довести data/problem layer до нужной постановки
Нужно:
- добавить `w8a`;
- явно оформить logistic-regression oriented path;
- явно оформить разбиение на `10` клиентов;
- не смешивать article-aligned path со старым backward-compatible path, если тот будет сохранен.

### Шаг 4 — реализовать композицию компрессоров
Нужно ввести явную и тестируемую pipeline abstraction, которая поддерживает минимум:
- `DB(4-bit)`;
- `TopK(10%)`;
- `DB(4-bit) -> TopK(10%)`.

Порядок применения фиксирован:
- `gradient -> DB(4-bit) -> TopK(10%)`.

### Шаг 5 — заменить грубый учет коммуникации на точный
Нужно логировать и считать:
- число переданных координат;
- биты на значения;
- биты на индексы при sparsification;
- cumulative bits;
- `kbits_per_n = cumulative_bits / 1000 / n`.

Ось X на графиках должна строиться только из этих логов.

### Шаг 6 — ввести общий communication cutoff
Нужно:
- уметь задавать общий budget cutoff для family A и family B;
- останавливать run, когда общий budget достигнут или минимально превышен;
- не продолжать вычисления сильно дальше cutoff;
- переиспользовать готовые CSV, если это безопасно.

Это критично для MacBook Pro M4 Pro.

### Шаг 7 — собрать family A
Нужно:
- проанализировать, какие старые reference curves уже есть в архиве;
- сохранить релевантные старые reference curves;
- добавить новые обязательные curves:
  - `EF21 + Top-10%`
  - `EF21 + DB(4-bit)`
  - `EF21 + DB(4-bit) -> Top-10%`
- сделать графики по:
  - `mushrooms`
  - `a9a`
  - `w8a`.

### Шаг 8 — собрать family B: static vs dynamic
Нужно:
- привести легенды к читаемому виду;
- сохранить `p=2`, `p=4`;
- добавить `p=8`;
- ориентировать семейство на `4-bit` setting;
- явно документировать, какое dynamic-rule используется в коде.

### Шаг 9 — зафиксировать CSV contract
Минимальный состав полей CSV:
- `seed`
- `dataset`
- `method`
- `compressor_pipeline`
- `dynamic_mode`
- `p`
- `bits_per_value`
- `k`
- `k_ratio`
- `iteration`
- `cum_bits`
- `kbits_per_n`
- primary convergence metric
- optional runtime

### Шаг 10 — добавить минимальную валидацию
Нужны хотя бы smoke-checks для:
- загрузки датасетов;
- compressor composition;
- monotone communication accounting;
- cutoff stopping;
- CSV generation.

Также полезен dry-run mode.

## 4. Критерии готовности

Работа по small-datasets считается завершенной только если:

1. Есть единая точка входа для `mushrooms`, `a9a`, `w8a`.
2. Есть pipeline `DB(4-bit) -> TopK(10%)`.
3. Есть static/dynamic runs для `p in {2,4,8}`.
4. Все кривые внутри одной family заканчиваются на одном `Ox = kbits / n`.
5. Лишние итерации после достижения budget cutoff не выполняются.
6. Все обязательные кривые логируются в CSV.
7. Легенды графиков человекочитаемы.
8. Код остается простым и поддерживаемым.
9. Время исполнения разумно оптимизировано под **MacBook Pro M4 Pro**.
